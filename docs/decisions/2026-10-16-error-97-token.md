# Decision: Add error-97 tone and errorContainerHigh role

- **Date:** 2026-10-16
- **Type:** Changed assumption / approved design-token correction
- **Status:** Approved (Product Lead)

## Context

The Account screen's "Log out of all devices" button needs a lighter error
container background than the supplied `error-container-color`
(Error 95, `hsl(7, 100%, 95%)`). The Product Lead requested "error 97".

The supplied `design-tokens.tokens.json` error ramp contained only Error 95,
Error 38, and Error 29. No Error 97 tone existed, and
`.agents/rules/design-system-rule.md` forbids inventing a color without a
recorded design decision.

## Decision

Add a new Error 97 tone and a semantic role for it:

- **Primitive:** `primitive-color-error-97` = `hsl(7, 100%, 97%)`
  (light error container high).
- **Semantic role (light):** `error-container-high-color` = `hsl(7, 100%, 97%)`.
- **Dark:** set to the unresolved magenta placeholder `hsl(300, 100%, 50%)`
  because the dark error roles remain unresolved per the design-system rule.
  Dark usage stays blocked.
- **React Native mapping:** `rawTokens.color.light.errorContainerHigh` /
  `rawTokens.color.dark.errorContainerHigh` in
  `apps/frontend/src/theme/tokens.ts`.

## Applied to

- `apps/frontend/src/features/settings/AccountScreen.tsx` — "Log out of all
  devices" button background uses `colors.errorContainerHigh` (text
  `onErrorContainer`, stroke `error`).
- Token source: `design-tokens.tokens.json` (light + dark).
- Primitive registry + generated CSS: `convert-tokens.js`, `design-tokens.css`
  (`npm run tokens:generate`).

## Sources updated together

`design-tokens.tokens.json`, `convert-tokens.js`, `design-tokens.css`, and
`apps/frontend/src/theme/tokens.ts` were updated in the same change so the
source, generated output, and central mapping stay traceable.

## Remaining risk

Dark mode for this role is unresolved (magenta placeholder). This decision does
not resolve the PRD F7.3 dark-theme gap.
