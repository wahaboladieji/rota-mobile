# Decision: Add error-98 tone for cancellation notice card

- **Date:** 2026-10-18
- **Type:** Changed assumption / approved design-token addition
- **Status:** Approved (Product Lead)

## Context

The Billing Overview screen's "Cancellation scheduled" notice card needs a distinct, softer error tint background than Error 95 (`hsl(7, 100%, 95%)`) and Error 97 (`hsl(7, 100%, 97%)`). The Product Lead requested:
- Background: "error 98"
- Stroke (border): "error" (`hsl(359, 100%, 38%)` / `#BA1A1A`)
- Top-right remove option placed as a cancel icon (`XIcon`)
- Description text summarized to 2 lines

The supplied `design-tokens.tokens.json` error ramp contained only Error 95, Error 38, and Error 29 (with Error 97 added on 2026-10-16). No Error 98 tone existed, and `.agents/rules/coding-standards.md` / `design-system-rule.md` requires recording token additions.

## Decision

Add a new Error 98 tone:

- **Primitive / Role (light):** `rawTokens.color.light.error98` = `hsl(7, 100%, 98%)`.
- **Stroke / Border:** uses existing `colors.error` = `hsl(359, 100%, 38%)` (`#BA1A1A`).
- **Dark:** set to the unresolved magenta placeholder `hsl(300, 100%, 50%)` because dark error roles remain unresolved per the design-system rule. Dark usage stays blocked.
- **React Native mapping:** `rawTokens.color.light.error98` / `rawTokens.color.dark.error98` in `apps/frontend/src/theme/tokens.ts`.

## Applied to

- `apps/frontend/src/features/billing/BillingOverviewScreen.tsx` — "Cancellation scheduled" card background uses `colors.error98` (`hsl(7, 100%, 98%)`), border stroke uses `colors.error` (`#BA1A1A`), top-right remove option cancel icon (`XIcon`), and 2-line summarized description text.

## Remaining risk

Dark mode for this role is unresolved (magenta placeholder). This decision does not resolve the PRD F7.3 dark-theme gap.
